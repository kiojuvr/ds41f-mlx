# Provenance policy

This page owns **attribution, source/input identity and evidence inheritance**.
[Correctness](correctness.md) owns semantic authority;
[runtime admission](runtime-admission.md) owns installed execution/host boundaries;
[operations](operations.md) owns setup; [delivery strategy](reference-release-and-promotion-strategy.md)
owns one-way publication/projection. Provenance is not an at-HEAD qualification badge.

## Official checkpoint identity

Official DeepSeek-V4.1-Flash data is read-only. Checkpoint tensor/storage/atlas and
metadata identity must match the selected contract. Startup's exact shard-byte
verification/cache is distinct from historical LFS/size metadata or a cheap
checkpoint fingerprint. No copied provenance receipt admits changed weights.

## Official source identity

Reviewed official DeepSeek semantics outrank implementations and references.
Derived owned validators preserve their official origin and bounded observed
predicates. Tokenizer/recipe identity is separate from checkpoint weights and must
remain exact where it affects canonical encoding, hashing or model inputs.

## Native source ownership

The repository owns the imported native foundation, attention/session, HC, MoE,
Engram, blocks, text runtime, sampling/generation and bridge/residency material.
Local ownership does not make this complete native core the selected production
engine. Current OFF model execution is first-party `model_execution`; ordinary
MTP retains pinned physical oMLX authority. [Scaffold roles](scaffold-classification.md)
distinguish selected, shared, reference and experimental material.

## Import manifests and verification

`artifacts/provenance/{legacy-import,native-core-closure}.json` retain original
hash/classification/transformation/reachability and closure evidence.
`tools/check_legacy_import_integrity.py` and
`tools/check_native_import_dependencies.py` check their declared import boundaries.
`tools/check_repository_self_containment.py` owns document/source-path checks;
its final evidence-navigation versus normative-dependency reconciliation is
separate from model qualification. None of these promotes an execution selector.

## Explicit MTP candidate provenance

Installed wheels inherit reviewed attributed exports/patches, locks/toolchain and
qualified dependency/native identities. Source equality, developer paths, compiler/
SDK and local MTP/OFF seals are not ordinary startup requirements. Execution,
semantic assets and loaded native identity are exact where admitted; unrelated/
uninvoked host link paths use explicit ABI/loadability compatibility, not total
Homebrew/OS inventory equality. Do not observe/reseal today's drift into approval.

## External runtime dependencies for standard-off

The first-party OFF numerical/model/state owners still invoke admitted MLX/Metal,
mlx-lm and lower-level stateless acceleration/tokenizer/recipe/image primitives.
First-party ownership does not remove those attributed dependencies or allow
numerical drift. MTP's separate installed payload is not an OFF model fallback.
Exact profile identities live in admission/package material, not a duplicated
checkout-path/revision list here. Operators use installed environments, not
external editable donor checkouts or source overrides.

The source edition (`c1d1f716:docs/archive/editorial-baseline/provenance.md.txt` in Git) retains former
M18/M20 worktree/path requirements, explicit revisions and M45–M47 attribution/
admission narrative. Historical native and oMLX origins remain evidence, not
current startup instruction or automatic approval of later payloads.

## Tested runtime identity model

Bind evidence to execution-relevant inputs and qualification tooling separately;
documentation/receipt commits need not invalidate unchanged model math. That is
not permission to ignore executable source, bytecode, ignored native images,
checkpoint/tokenizer, dispatch, state or build changes. Clean Git status and an
ancestor receipt alone cannot prove selected payload identity.

The older cheap `ds41f_mlx.provenance` inspector and `qualify --check-evidence`
attestation checks describe their source/environment evidence models; they do not
replace installed admission, affected model evidence or source-projection receipts.
Inherit expensive evidence only with explicit unchanged-owner/scope reconciliation,
original artifacts/provenance, classified intervening changes and the applicable
new input boundary. Unknown/mismatched executable differences require review;
not every mismatch is fixed by rerunning a metadata tool or full campaign.

## External architecture and implementation sources

- DwarfStar supplies dense prefill architectural lineage, not semantic authority.
- oMLX supplies attributed algorithms/primitives, historical controls and MTP
  physical authority—not official semantics or OFF target-transaction authority.
- M45/M46 derived target/state sequencing and subsequent first-party OFF math
  retain per-file MIT/Apache attribution and licenses; donor top-level licensing
  must not substitute for the actual imported subtree's license.
- Historical native source is implementation origin/reference evidence only.

Preserve exact donor/input digests, license notices and original receipts. Source
closure, execution-owner closure and platform/dependency-count reduction are
different decisions. No donor supersedes official checkpoint/reference semantics;
compilation changes no attribution material, admission manifest or release payload.
