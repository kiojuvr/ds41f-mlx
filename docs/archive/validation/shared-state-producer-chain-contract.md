## Producer ownership audit

Pinned source/config review shows the initial hypothesis needed refinement:

| field | relevant producer for layer24/25 | source branch | consumer seam |

| `shared_attn.compress_kv` | layer 20 | `Attention._compress_kv`: kv-source layer sets `shared_attn.compress_kv` to its cache and writes RoPE+FP4 compressed latent | layer24 and layer25 read it |
| `shared_attn.index_k` | layer 20 | `Indexer.forward` owns-k path: `wk -> k_norm -> RoPE -> FP4`, publishes `shared_attn.index_k` | layer20 scoring and layer24 Indexer read it |
| `shared_attn.candidates` | layer 20 | candidate-source branch: `select_candidate_blocks(...) -> shared_attn.candidates` | layer24 candidate-consuming Indexer reads it |
| `shared_attn.topk_idxs` | layer24 for layer25 | layer20 also publishes preliminary top-k, but layer24 is an index source and overwrites it before layer25 consumes | layer25 reads layer24 top-k |

Layer 2 is an earlier KV/index source and is executed in the runner as preliminary provenance, but layer20 is a later KV/index/candidate source and overwrites the fields relevant to layer24/25.  Therefore the source-backed ownership claim for the 24/25 seam is layer20 for `compress_kv`, `index_k`, and `candidates`.
