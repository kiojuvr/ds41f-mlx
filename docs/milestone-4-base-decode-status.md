## Actual oMLX cache slot mapping

For every admitted layer:

| Slot | Meaning | M4 admission behavior |
| --- | --- | --- |
| 0 | offset/frontier | `mx.array([token_frontier], int32)` |
| 1 | packed local window KV | M2 BF16 `uint16` `[1, rows, 512]` is viewed as `mx.bfloat16` and packed with `pack_activation(bits=8, group_size=32)` to `[1, rows, 528]` |
| 2 | packed compressed KV | source layers 2/8/14/20 use M2 BF16 state packed with `pack_activation(bits=4, group_size=16, e4m3_scale=True)` to width `288`; non-source layers get empty packed arrays |
| 3 | packed index K | source layers 2/8/14/20 use M2 BF16 state packed with `pack_activation(bits=4, group_size=32)` to width `68`; non-source layers get empty packed arrays |
| 4 | compressor pending KV | M2 pending state if present, otherwise empty `[1, 0, 512]` BF16 |
| 5 | compressor pending gate | M2 pending gate/score if present, otherwise empty `[1, 0, 512]` BF16 |
| 6 | Engram history | layer 0 receives oMLX `NgramHash` lookback history regenerated from committed `token_ids` only; other layers receive empty int64 history |

Candidate/top-k/shared-publication M2 evidence is validated as present and recorded as intentionally regenerated by oMLX target forward from the durable compressed/index state; it is not silently discarded.

- The known-good local oMLX baseline remains `docs/archive/reference/omlx-known-baseline.md` (official checkpoint, long-context server/admin production runs, 29-37 tok/s decode at 32K-200K, ~293 GB peak). Current evidence shows that practical oMLX-class behavior begins at the scheduler/GenerationBatch execution substrate, not at ad hoc direct one-token `_forward` calls.

## Transaction/lifecycle behavior

`OMLXDecodeSession` uses lightweight transaction snapshots of cache slot references, left-padding/length metadata, token-history chunk count, frontier, and committed step count. It does not deep-copy cache tensor payloads per token and no longer copies the full CPU token history per step. On injected failure after target forward but before eval/commit, the runner verifies frontier, offsets, and Engram history are restored.

Fork uses shared immutable MLX array references plus independent `DeepseekV41Cache` containers/frontiers. Child decode does not mutate parent state. Reset replaces request-local caches via `language_model.make_cache()` and clears token/frontier state without unloading model-static checkpoint or Engram backing.
