# Target dense prefill: work geometry, native dispatch and attainable throughput

Base: `2f928cd`. Official DeepSeek-V4.1-Flash, M3 Ultra / 512 GB,
MLX 0.32.2. **No production execution change selected.** Normal target primitive
reuse across P6 measures substantial prefix headroom but changes window bytes and
regresses a paired 32-token decode by 2.3%. The temporary integrated candidate was
restored to `2f928cd`; its patch and qualification are preserved as evidence.
Checkpoint, precision, cache authority, resources, planner, MTP, Web and release
remain unchanged. The ladder below is the unchanged native production baseline.

## Measurement authority

`tools/bench_target_prefill.py` loads the normally configured **first-party OFF
model**, using configured import paths **before** importing its numerical modules.
Every measurement runs `DeferredPrefillAppend`, seals its actual 40-object cache,
and evaluates all authoritative cache leaves. It then performs P5 on that same
list, the held-out terminal forward, eight greedy outputs, and (in final controls)
a real suffix append and eight continuation outputs. Replay/repack are asserted
zero and all idle cache frontiers are checked. Inputs are tokenized ordinary
English about caches, locality and bandwidth, truncated from a long repeated
passage; these are real model executions, not synthetic hidden tensors. They
exercise context/dispatch geometry, not a claim of corpus-wide routing statistics.

Receipts: `artifacts/target-prefill/`. `native.json` contains the complete
uninstrumented length ladder and subsequent bounded producer probes; its final
8192 probe failed because the initial observer materialized native few-row
GatherQMM nodes prematurely. **All ladder rows completed before that diagnostic
failure**. `final-controls.json` is the corrected complete PASS run, with
allocator-cache reuse, continuation, exact MoE-variant state comparisons and
real-operand replays. `cone-controls.json` and `suffix-controls.json` then test
work geometry and cross-boundary attention dispatch; `candidate-integrated.json`
measures the temporary integrated helper, now restored/not selected. `summary.json` is regenerated by
`tools/summarize_target_prefill.py`.

The initial `scaling*.json` and `producers.json` accidentally imported numerical
modules before applying configured paths, selecting the separately admitted
**portable** profile. They are retained as an explicitly labeled diagnostic
control, **not normal native production throughput**. Admission receipts expose
this distinction (`native_profile`, binary hashes, working-set policy). Checking
`has_symbol` in a separately started interpreter was insufficient to establish
what the already-loaded benchmark dispatched. The corrected native run resolves
the apparent discrepancy with previously qualified large-context throughput.
No runtime/native dependency was installed, patched or promoted to do so.

A 60-second Instruments Metal System Trace attempt generated excessive capture
memory and interrupted the initial portable run after its first 4096 case.
That incomplete trace supplies **no GPU duration or dispatch-count claim**.
The native ladder ran separately after all traced model/capture memory retired.
Actual dispatch is established by real-operand producer calls plus the admitted
native factory/Metal implementations, not by timing that failed trace.

## Completed latency and scaling

Warm second pass, normal native profile, freed-buffer allocator cache cleared
between fresh cases (production's existing 32 GiB cap remains in force):

| Prefix positions | Completed prefill s | tok/s | Logical block rows/s |
|---:|---:|---:|---:|
| 64 | 0.283 | 226 | 9,056 |
| 128 | 0.395 | 324 | 12,975 |
| 292 | 0.716 | 408 | 16,314 |
| 512 | 1.123 | 456 | 18,229 |
| 1024 | 2.120 | 483 | 19,324 |
| 2048 | 4.080 | 502 | 20,079 |
| 4096 | 7.877 | 520 | 20,801 |
| 8191 | 15.604 | 525 | 20,997 |
| 8192 | 11.140 | 735 | 16,876 |
| 16384 | 19.336 | 847 | 18,196 |
| 32768 | 35.895 | 913 | 18,931 |
| 65536 | 70.504 | 930 | 18,933 |

“Logical block rows” counts actual full-block row work, not nominal prompt tokens:
ordinary ranges do `40*N`; source-only ranges do `20*N`; completing ranges do
`20*N + 24,150`. It excludes source publication/preparation and is a normalization,
not an exact FLOP inventory. The decoder query rows are
`1 + (39-layer)*127`, whose sum over layers 20..39 is 24,150. Layer20 additionally
publishes global source state from the full encoder-final representation.

There are **two different transitions**:

* Below 8192, all 40 layers process the full prefix. Throughput approaches its
  approximately 525 tok/s regime smoothly. A descriptive fit is about 0.15 s plus
  1.89 ms/token; the intercept is not all fixed Python/request overhead. Expert
  occupancy, weight reuse, dense dispatch utilization and attention key geometry
  change with shape and routing. Actual graph-enqueue overhead is much smaller.
* At 8192 the planner replaces full decoder-prefix work with a bounded dependency
  cone. The 8191→8192 latency drop is **work elimination**, not a kernel suddenly
  becoming twice as efficient. Logical block throughput actually falls at this
  boundary because the decoder cone includes many narrower shapes. At 16K and
  beyond encoder source work amortizes its roughly 3.1 s completing tail.
  Large nominal tok/s is therefore not a valid kernel-efficiency comparator for
  a 292-row all-layer prefill.

At 32K and 64K, source-only/completing segments use two 8192 encoder tiles per
layer inside 16384-row carry segments. More boundaries do not cause a large
collapse: the measured steady normalized work rate is almost identical.
Context-dependent indexing/cache work grows, but is not dominant through 64K.
This does not extrapolate constant throughput to 1M: existing very-long-context
receipts already show indexing/attention/context costs growing at much larger
frontiers.

## Production versus synchronization

At 292 rows, native prefix enqueue is 19 ms and later authoritative-state eval
is 697 ms. At 1024 the split is 1.095 / 1.025 s; at 4096 it is 4.072 / 3.805 s.
At 8192 it is 8.052 / 3.088 s; at 64K it is 67.347 / 3.157 s.
These are **not independent component timings**.

The producer chain is embedding/hash → HC → target attention/projections →
routing/expert/shared projections → HC → next layer, with source cache and
publication branches. P7 async evaluation around SSD Engram dependencies submits
upstream target work. Larger graphs also pay evaluation/submission debt before
Python enqueue returns. P6 persistent-source eval pays encoder/source graph debt
before retiring its ancestry; final cache eval pays the remaining decoder graph.
P5 then evaluates an ordinary genuinely new terminal-token forward. Moving these
barriers alone relocates debt; it does not remove arithmetic.

The diagnostic observer prepays inputs and evaluates outputs at producer sites.
Its barrier overhead and extra last-block output evaluation perturb production
laziness, fusion and allocation. Initial replay-free native probes inflated
292-row completion from 0.716 to 1.058 s, and 2048 from 4.080 to 4.640 s.
Final probes additionally contain deliberate operand replays. **Do not sum their
regions or report their ratios as production GPU percentages.** Their valid uses
are identifying producers, real shapes, native calls, occupancy, and confirming
that state is unchanged under the corrected observation boundaries.

In particular the one-row native Expert pipeline consumes unevaluated GatherQMM
nodes and fuses them into `deepseek_v41_grouped_expert`. Evaluating those nodes to
“measure matmul time” destroys its input contract. The corrected observer treats
that region as opaque, observing completed MoE output instead. No production
materialization boundary was added.

## Real shapes and dispatch

Source audit hashes/locations are recorded in `source-dispatch.json`; admitted
library/metallib identities are in each receipt. M3 is pre-NAX.

* Dense FP8 projections have BF16, official FP8-rounded inputs and packed MXFP8
  weights/scales. At 292 rows, examples are `[1,292,5120] → 1280/512`,
  `[1,292,1280] → 32768`, `[1,292,8192] → 5120`, and shared FFN
  `5120 → 2304 → 5120`. Engram's two projection boundaries include
  `[1,N,6144] → 25600`. MLX flattens row-contiguous non-batched input to M=Ntokens;
  native non-NAX transposed QMM is BM32/BN32, with split-K when its grid would
  otherwise be underfilled. Quantization and projection outputs retain BF16.
* Attention output projection also has a real grouped BF16 GEMM:
  `[1,N,8,4096] × [8,1024,4096]`, followed by the width-8192 output projection.
  It is not another generic MXFP8 projection merely because it lives in Attention.
* Native packed attention receives Q `[1,64,N,512]`, uint8 local KV of width
  **528**, pooled KV width **288**, uint32 selected IDs, and FP32 sinks. Its
  fixed factory is BK64/DC32/H64/D512/WM8, dispatching **one 256-thread group per
  query** and processing all heads with shared packed-KV reuse. Ordinary local
  capacity is 128; selected pooled keys reach 512. This is the ordinary target/
  encoder dispatch. **Before the fix, P6 suffix queries bypassed it.** Thus keys/query initially
  grow with prefix length and later saturate, while index selection still depends
  on the available context. It does not unpack/repack the full persistent cache.
* MoE routes six experts/token among 384. FP8-rounded token rows are reused for
  shared/routed input quantization, then sorted/gathered to `[6*N,1,5120]`.
  Gate/up weights are `[384,2304,640]` uint32 plus uint8 scales;
  down weights are `[384,5120,288]`. The normal native path constructs a GPU
  block list, projects gate/up together, applies weighted/limited SwiGLU with
  FP8 activation quantization, projects down, then combines in original order
  with the shared expert. It does **not** use the stock GatherQMM branch observed
  in the portable control. Existing native variants have BM8/16/32, BN32/BK32
  and 64 threads; the current crossover uses BM16 below 16,384 routes and BM32
  above it. The grid includes a conservative maximum-block extent; unused
  blocks exit using GPU-produced block count, without a host count readback.

Real routing is strongly nonuniform, not six uniformly random assignments:
292-row mean active experts ≈98, mean maximum rows/expert ≈207; BM16 useful-row
fraction ≈0.636. At 2048 these are ≈127 / 1391 / 0.908. Short prefixes are not
well modeled by dividing routes by all 384 experts. This padding/utilization and
repeated expert-weight traffic explain much of the short-shape regime.

## Which regions dominate, and what headroom is real?

Native routed projections plus dense/grouped projections dominate interactive
and medium work. Packed attention becomes appreciable as keys/query reach their
cap, but is not the principal unexplained fresh-prefix expense in the native
profile. In the portable control, rounded attention is much more expensive;
that distinct execution profile must not be confused with native steady prefill.

Completed isolated real-operand replay rejects a general “dequantize MXFP8 once
and use BF16 GEMM” campaign. At 2048, the large Q projection is approximately
7.7 ms by either path; the large output projection is also approximately 7.7 ms.
Engram projection is approximately 28 ms versus 27.7 ms. Dequantization adds
allocation/memory and some shapes have nonzero BF16 output differences. These
major projections already achieve roughly **22–23 TFLOP/s of useful GEMM work**
on this machine. There is no substantial proven E2E gain from replacing them.
This is a real-checkpoint operand control, not peak numbers from a synthetic GEMM.

Sorted real Expert replay, including block construction, both gate/up, activation
quantization and down, also shows efficient steady arithmetic: at 8192, BM32
processes a full real routed layer in approximately 151–154 ms (first four layers),
about 23 TFLOP/s of useful projection work. BM16 takes 164–166 ms and BM8 takes
214–215 ms. At 2048, BM32's small isolated advantage over the current BM16 is
only about 1–4%; it is not grounds for a broad custom-kernel or crossover campaign.

For very small routes BM8 is genuinely faster in isolation. But the full native
pipeline control using BM8 through 3072 routes measures:

| Prefix | Normal s | BM8 control s | E2E conclusion |
|---:|---:|---:|---|
| 64 | 0.274 | 0.246 | 29 ms saved, 1.12× prefill |
| 128 | 0.391 | 0.375 | 16 ms saved, 1.04× |
| 292 | 0.712 | 0.734 | regression |
| 512 | 1.118 | 1.187 | regression |
| 1024 | 2.111 | 2.115 | unchanged control above crossover |

Every variant replay is exact on the measured Expert outputs; full controls
match output IDs, all settled cache-state digests, continuation IDs/digests and
frontiers. Decode is unchanged within run variation. Nevertheless this broad
crossover is **rejected**: it does not improve the main fresh interactive workflow
and introduces first-use cost. A more narrowly qualified ≤64-row crossover has a
small finite opportunity, not the next substantial production boundary.

There is no absolute proof that every kernel is hardware-optimal. The evidence
establishes that the large projection regime is close to the best measured
real-operand matrix path, and that easy alternative dispatches do not provide
large gains. Useful FLOPs alone undercount short-route padding; an optimistic
all-regions-at-GEMM-rate bound is not an implementable speedup claim.

## Overhead, reuse and lifetime

The native OFF capability acquires its working-set budget before model/prefix
allocation and retains its existing bounded allocator policy. There is no late
residency transition to remove here. Keeping the allocator cache rather than
clearing it changes warm 292 prefill 0.716→0.712 s and 1024 2.120→2.111 s, well
under 1%; allocation reuse is not the dominant missing throughput.

First-use is separate: first 64-row native pass 0.453 versus 0.283 s; shape first
use adds smaller effects at later lengths. Checkpoint admission/load (including
payload hashing) is measured separately, approximately 5–6 minutes in these OFF
runs, not charged as GPU prefill. These are process/shape first-use observations
with existing system compilation caches, not a clean-system JIT bound.

At warm native 64K, terminal bootstrap is about 67 ms, eight outputs about
408 ms; subsequent ordinary suffix startup about 166 ms and eight continuation
outputs about 408 ms. No prefill gain is being purchased with slow decode or
cache repacking. Engram SSD scheduling remains borrowed/overlapped; its added
host/scheduling residual is small relative to full target work in warm probes.

PublicationManager keeps cumulative exact tensor references. There is no
full-cache repack, prompt replay, or proven identical-input repacking cycle.
The source-boundary eval/owned cone copies are required lifetime cuts; their
wall interval mostly resolves upstream model work. Dense carry writes, Engram
microtile concatenation and routed token-row gathering do add representation
traffic, but do not explain seconds on these native shapes. Existing P8
[tile-carry controls](p8-e2e-dataflow-representation-audit.md) already rejected
replacing dense transport wholesale. The new native shape/replay evidence does
not justify restarting that campaign.

## Unselected headroom: P6 bypasses the normal target primitive

The integrated-pipeline audit found a more valuable issue than a leaf crossover.
`OmlxV41SuffixMath._attention` decomposes attention to avoid producing global
source state twice, but always called `packed_sparse_attention`. In a native
model, ordinary target Attention instead uses the already-admitted 64-head native
primitive. The decomposition therefore **lost dispatch reuse across the P6
architectural boundary**. At 8192 the encoder pays about 8.05 s and the completing
query tail about 3.09 s; much of that tail is the slower first-party explicit-index
rounded-attention implementation, not detach/copy or cache certificate work.

The old comment asserted that native attention required a full old window.
Inspection of the actual native Metal implementation disproves this:

```text
local_offset = localL - qL                 # actual old rows: 127
local_end(t) = local_offset + t + 1
window_first(t) = local_end(t) - 128       # t
```

P6's explicit local indices are likewise `t + arange(128)`, including the current
query row. Absolute `q_offset` remains unchanged for pooled-key causal masking.
The prepared 127-row window is supported; it is not an off-by-one substitution or
permission to read a stale cache row. Native factory accepts this actual geometry.

The temporary integrated candidate added `_packed_suffix_attention` to select that same admitted
normal-target primitive **only** for first-party language math, BF16, 64 heads,
head width 512, window 128, exactly 127 prepared old rows and >8 query rows.
Donor/MTP, portable, few-row and other geometries keep the original path. No new
kernel, native artifact, profile, environment knob, eval, synchronization, source
publication or planner change is introduced. The native pipeline is already used
by the encoder, so this does not introduce a new shape-specific kernel/JIT family.

The real-model tool control removes about **1.85 s** at both 8192 and 32K,
consistent with a fixed completing-tail bottleneck. It changes the producer of
attention outputs, rather than merely moving their synchronization:
8192 completion falls about 3.09→1.24 s while source/enqueue remains about 8.05 s.
The same improvement appears in the temporary integrated helper without monkeypatches.
Dense QMM, routed expert dispatch, Engram and cache production are unchanged.

This is not a byte-identical legacy decoder-window claim. Normal native attention
and the explicit-index rounded implementation have different reduction execution.
The control retains exact encoder/source/history state, layout, precision and
frontiers, and identical eight initial output IDs, but suffix window bytes
change from layer21 onward. At 8192 the fixed eight-step raw continuation differs
at steps7/8 **after both paths' first EOS token**; 32K/64K raw continuation IDs
match. The benchmark deliberately continues stepping with no EOS stop IDs to
measure arithmetic throughput, so those post-EOS IDs are not ordinary completed
turn output. They still demonstrate numerical trajectory divergence: do not claim
all continuation IDs or all legacy state bytes are identical. Native persistence/
restore and full OFF R1 separately qualify actual state and semantic boundaries. An ordinary 6144-row control independently establishes
that native suffix attention agrees with normal native-target state through
layer29; remaining narrower-shape projection differences first appear at layer30.
The producer is identified, not labeled “cache-copy overhead.” These finite checks
are not a universal token-equivalence theorem or authorization to change the
qualified arithmetic trajectory. Normal-target primitive reuse is a credible
boundary, not numerical/state authority borrowed from another runtime.

### Selection decision: no steady regression accepted

| Prefix | Unchanged warm s | Integrated candidate s | Prefix time saved |
|---:|---:|---:|---:|
| 292 | 0.712 | 0.712 | no change |
| 8192 | 11.104 | 9.249 | 1.855 s / 16.7% |
| 32768 | 35.869 | 34.010 | 1.859 s / 5.2% |
| 65536 | 70.671 | 68.810 | 1.861 s / 2.6% |

An eight-token decode in the separate integrated run was 0.423–0.426 s versus
0.404–0.408 s in the earlier controls. Do not dismiss that by assuming that an
unchanged decode function implies unchanged performance. We ran a same-resident-
model control with four repetitions per mode and 32 fixed decode steps. Warm
median prefix falls 11.114→9.239 s, but subsequent decode is **1.594→1.630 s**,
20.08→19.63 tok/s (**2.3% slower**). All 32 initial output IDs match. Eight-step
continuation is 0.3996→0.4026 s (~0.75% slower). The 4% separate-run first-eight
comparison is not the steady paired estimate. Nor is this proof that native
attention's own kernel causes the decode difference: prefix numerical state,
routing/indirect reads, phase/order and residency can affect an unchanged decoder.
The observation remains a regression to resolve, not a reason to move timers.

The following candidate checks all pass:

- `native-state-qualification.json`: normally admitted native OFF, contexts8192
  and32768; first-party numerical ownership, zero full prompt replay/repack,
  same-list idle append, exact idle artifact persistence/restore and matching
  restored continuation. No displaced numerical imports/calls.
- `r1-off.json`: fresh **full OFF R1**,24 gates, CONFORMANT. R1 material/verifier
  untouched. Its frozen OFF source selects the portable admission; it qualifies
  actual public semantic/state boundaries, **not native P6 arithmetic identity**.
- `unit-tests.log`:66 tests/26 subtests for geometry/ownership, P5/P6/P7 and
  resources. `mtp-resource-tests.log`: source-clone MTP resource tests pass.
- `self-containment.log`: static checker blocked by existing `M2` wording in
  unchanged `docs/session-state.md`; unrelated canonical cleanup is not part of
  this investigation. New documentation classification/links are checked separately.

Passing R1 and self-restore is insufficient to call the changed native window
trajectory equivalent, or to waive the paired decode result. Therefore **no hot-
path change ships**. `candidate-suffix-math.patch` preserves the exact temporary
candidate; source hashes in its qualification identify it. `--suffix-ab` implements
the guarded candidate only in the diagnostic tool. Production package execution
is byte-for-byte restored to `2f928cd`; its normal MTP source seal is refreshed
against the existing unchanged native recipe wheel, without rebuild/promotion.

The highest-value next production boundary is thus **P6 attention producer/
precision alignment with normal target dispatch**, with early/steady decode,
native affected semantic and state qualification included in the acceptance
criterion. The 1.85 s is measured headroom, not a promised deployable speedup.
Full-prefix versus suffix query/source geometry and rounded reduction topology
should be aligned before a broader kernel campaign or blanket planner change.

### Rejected combined topology change and next boundary

A diagnostic completing-cone plan below the current threshold gives warm:

| Prefix | Existing ordinary s | Cone / legacy attention s | Cone / native attention s |
|---:|---:|---:|---:|
| 4096 | 7.837 | 7.156 | not tested |
| 6144 | 11.709 | 9.152 | 7.285 |
| 7168 | 13.619 | 10.132 | not tested |
| 8191 | 15.578 | 11.133 | not tested |

Thus useful additional headroom exists at the **completion topology/capture
contract**, not in globally speeding dense GEMM. It is deliberately **not combined
as a production change**. These plans change decoder-window values and execute
only tail rows at layers37..39, while current MTP priming harvests required prompt
hidden rows from those layers. A blanket threshold change would violate those
capture contracts. Lowering the frozen 8192 threshold needs explicit owner-aware
cache-only versus hidden-capture requirements and proportional native numerical,
state, cancellation and multimodal qualification. The fixed 2541-row input cone
also makes very short prefix savings much smaller than halving nominal work.
Current capacity, threshold, rounding, segment commands and P5/P6 state contracts
remain untouched. This is the next production optimization boundary after the
dispatch-reuse investigation, not an authorized blanket chunk-size knob.

## Reproduction

Use the normally admitted OFF interpreter and configured source/native paths.
Only one model may be resident at a time. No executable model source is changed
by the diagnostic controls.

```sh
.venv/bin/python -m tools.bench_target_prefill \
  --output artifacts/target-prefill/native-reproduction.json
.venv/bin/python -m tools.bench_target_prefill \
  --lengths 64,128,292,512,1024,8192,65536 \
  --moe-ab 64,128,292,512,1024 --probe-lengths 64,128,292,2048,8192 \
  --dense-replay --moe-replay --keep-cache --continuation \
  --output artifacts/target-prefill/final-controls.json
.venv/bin/python -m tools.summarize_target_prefill artifacts/target-prefill
.venv/bin/python -m pytest -q tests/test_prefill_fp8_mlx_p6.py \
  tests/test_prefill_fp8_mlx_p7.py tests/test_mtp_resources.py
```

For the unchanged-production/tool-only candidate suffix control:

```sh
.venv/bin/python -m tools.bench_target_prefill \
  --lengths 6144,8192,32768 --p6-ab 6144 --suffix-ab 6144,8192,32768 \
  --keep-cache --continuation --output artifacts/target-prefill/suffix-controls.json
```

`--suffix-ab` patches only the tool candidate; default baseline is unchanged
production. To reproduce the paired decode control add `--decode-tokens 32`,
`--lengths 8192 --suffix-ab 8192 --repeats 4 --keep-cache --continuation`.
The original portable and failed observer/trace attempts are explicitly separated
above; they are not silently promoted into completed native/R1 proof.
`2f928cd` remains the full OFF/MTP production semantic baseline. Optional
integrated-candidate reproduction applies `candidate-suffix-math.patch` to that
base, runs the recorded length/state/full OFF R1 commands, then reverts the patch;
it is not an authorized runtime selector or release/promotion operation.
