# Multimodal Runtime goal and completion contract

This CURRENT page owns the project goal and completion decision. Architecture
remains with the [upstream-first policy](implementation-plan.md#upstream-first-architecture-and-compatibility-policy),
[architecture](architecture.md) and [ordinary MTP](mtp-production-serving.md);
[capabilities](capabilities.md) owns support and [operations](operations.md) owns deployment.

**Multimodal-Runtime is operationally complete.** The proven implementation is
promoted into the existing Flash-1017 Production environment. The
[completion record](../artifacts/multimodal-runtime/production-completion.md)
binds the source, wheel, rollback and installed acceptance. No next development
phase or qualification campaign is selected.

## Goal and scope

Enable practical official DeepSeek Harness operation across image acquisition,
compatible complete Target/DSpark cache reuse, image offload, automatic compaction,
changed-projection reconstruction, continuation and reacquisition. This capability
is achieved within the Production envelope below. The finite
[E2E workload](../artifacts/multimodal-runtime/phase4-e2e-native.md) passed in one
load/official Session: nine sources, ten reads, four offloads, one durable
strict-shrink automatic compaction and nineteen settled/published native requests.
That evidence is authoritative for its exact implementation; it was not rerun for
promotion. The [operational review](../artifacts/multimodal-runtime/operational-gap-review.md)
found no concrete implementation blocker for normal operation in this envelope.

Long-running means no arbitrary cumulative image-inspection ceiling, **not**
unlimited current residency, storage, context, memory, time or guaranteed success
for every admitted input. A Harness Session is not a Runtime logical-session API;
Messages remains independent-request based. Exact logical Chat leases remain mandatory.

| Owner | Responsibility |
| --- | --- |
| Harness | Orchestration, tools, history/projection, attachments, offload, automatic compaction and session lifecycle |
| Recipe | Canonical Messages, multimodal ordering, tool identities, protocol conversion and accumulation |
| Runtime | MLX execution, admission, complete Target/DSpark integrity, canonical settlement and retirement |

DeepInfer remains the upstream multimodal/cache-aware execution reference. No
second history/cache owner, tool replay, hidden history repair, alternative
numerical algorithm or proprietary retry protocol is introduced.

### C2 numerical acceptance distinctions

Preserve the [numerical reference](../artifacts/multimodal-runtime/phase2-numerical-reference.md)
and [Step 2B-R2 differences](../artifacts/multimodal-runtime/phase2-step2br2-continuation.md).
Same-schedule reconstruction uses existing MTP P6/N−2/N−1/P5 with genuine selected
paired state, not an alternative forward. Different prefix partitions can change
floating arithmetic; no general tolerance or bitwise equivalence is established.
MTP versus ordinary full-sequence forward is an independent diagnostic, not a
bitwise reconstruction oracle. Frontier agreement and plausible prose alone do
not prove general numerical equivalence. Arbitrary changed-byte/order cases,
image-retaining compaction and intermediate numerical boundaries lack the full
native qualification matrix; no reconstruction-specific defect was established.

## Supported Production envelope

- Single operator, macOS/M3 Ultra **512 GB**, official Flash-1017, native GLM,
  paired MTP, delivered Recipe **0.2.0**, pinned oMLX and installed admission.
  One application/model lifetime per process; replacement means graceful process
  stop/start, not repeated in-process unload/reload. Loopback or explicitly trusted
  private LAN only, without authentication/TLS.
- Official Harness **0.2.1-rc.2**, native independent Messages, **Thinking OFF**.
  Initial integrated policy: image count **3**, quantum **1**, automatic pressure
  **8192**, retention **1024**, summary cap **2048**, ordinary output **1200**,
  generic provider retries **0**. See [operations](operations.md#visual-session-capacity-and-recovery)
  for the executed configuration and limitations. Other recommended reasoning or
  output settings have not inherited this integrated qualification.
- Current projections must fit **36,864 aggregate ViT patches** for independent
  reconstruction, with available current image bytes and whole-image-safe selected
  prefixes. No fractional-image execution or broader historical-discount
  reconstruction claim. Independent source-byte/pixel/body, context/output,
  queue, cache and physical-headroom guards remain enforced.
- Files are bounded/process-local/expiry-limited; offload does not purge Files or
  promise durable attachments. Missing bytes need client/operator action. Automatic
  offload follows recognized adapter policy, not arbitrary Runtime HTTP 400.
- Summaries can truncate or fail to shrink; Harness rejects without replacing
  history. Unsupported recovery safely refuses. Incomplete protocol or uncertain
  effects require reconciliation, never automatic Runtime request retry/tool replay.
  Lost exact Chat leases and native crash persistence remain unsupported.

## Closed phases and remaining non-blocking work

Phases 0–1 established contract and source audit. Phases 2–3 implemented/reused
bounded independent Messages reconstruction and exercised official lifecycle
transitions. Phase 4 completed the finite C8 workload; promotion now closes the
operational project, not every broad phase-exit qualification. The original phase
table and all attempt evidence remain at the links above, not a current backlog.

Remaining C2/C7 and broader C6/C9 qualifications are additional assurance, not
identified implementation blockers in this envelope. Windows DeepSeek Harness
qualification is **post-closure ordinary operational work**, not a prerequisite.
General Files extensions, durable File-ID storage, arbitrary numerical equivalence,
maximum capacity and additional endurance campaigns are not required for closure.
No Windows modification, numerical/kernel/Scheduler development, new campaign,
push, master merge or release tag follows from this disposition.
