# DeepInfer → official Harness compatibility audit

## Decision

**No remaining DeepInfer implementation gap is established that blocks or materially limits the currently supported, bounded Harness `0.2.2-alpha.2` / `deepseek-official` Native Messages integration. No further implementation is justified by this audit.**

This is not unrestricted Harness or DeepInfer parity. There are concrete unsupported recovery/resource combinations outside that envelope and unresolved broader numerical qualification. They are classified below, not relabeled as successes or new implementation tasks. Preserve the completed alpha.2 E2E and all-deferred correction. Production promotion remains a separate decision.

## 3. Cache-aware preparation: implementation versus advertised possibility

At examined DeepInfer revision (paths relative to [this exact source tree](https://github.com/deepseek-ai/DeepInfer/tree/553741557a57df44a46fb3ab72b6aafeaf945337)):

1. `deepinfer/ve/multimodal_processor.py:overwrite_prompt` expands placeholders from Processor geometry, records absolute `(start,count)` spans and request segments.
2. `_compute_and_strip_cached_images` strips binary only for the leading images with `start+count <= num_cached_tokens`. An intersected image retains its **entire** payload. `add` carries cached counts into the worker.
3. `deepinfer/model_executor/models/deepseek_vl.py:_split_cached_prefix` replaces only complete cached segments by equal-length dummy text. `multi_modal_mapper` restores zero crop/size/patch placeholders for cached images, preserving absolute alignment.
4. `deepinfer/ve/prepare_tensor_input_vl.py:_chunk_mm_metadata` selects images overlapping actual `[K−Q,K)`; `prepare_input_metadata_vl` filters zero crops before Vision and derives active patches. `deepseek_vl.py:get_input_embeddings/forward` invokes Vision only when applicable raw data exists.
5. **Caller caveat:** normal `deepinfer/engine/llm_engine.py:add_request` at lines 543–625 constructs a new Sequence and calls `multi_modal_processor.add(request_id, multi_modal_data)` **without** a cached frontier. `add` defaults to C=0. `scheduler.hpp:add_sequence` just queues. `fork_seq` supplies an explicit separate block/state reuse path; this is not proof of an ordinary request-wide image-aware content-addressed lookup. The previous Phase 1 review already recorded this distinction. Nothing since `9bd9cf2` wires a new frontier handoff.

Thus upstream proves useful conditional mechanisms, **not** a stronger generally deployed historical-image recovery guarantee to import blindly.

Local equivalents: `runtime/multimodal.py:prepare_multimodal` validates complete encoded containers and plans identities/geometry without normalized patch retention. `serving/production_mtp.py:_schedule_waiting` acquires a real compatible complete pair, then validates prefix/workload/sources before `_start`; `MultimodalInput.encode_new(C)` prepares only images beyond C through the pinned Model embedding adapter. Covered bytes are released, not retained as a hidden history authority. `ImageEmbeddings.merge` injects complete fresh rows at absolute positions. Full CPU source validation even on hits is intentional admission, not redundant ViT execution.

[Isolated probe](cache_boundary_probe.py), [result](cache-boundary-result.json): extracted the actual upstream strip method by AST, with lightweight segment doubles, no upstream/MLX/Torch import. Six frontiers for spans `[2,7)` / `[9,12)` verify cold, boundary, partial-first, complete-first, partial-second and complete-both stripping. **PASS**, supporting only that method contract; not a cache/model/integration qualification. Other boundaries were already unambiguous in source and retained tests, so no new campaign was needed.

### Partial image versus partial prefix

A prefix before an image or after one complete image is supported. A prefix **inside** an image is different. Local `paired_checkpoint.py:PairedCheckpoint.capture` forbids `start<C<end`; restore binds exact tokens plus digest/grid/start/length, and `MultimodalInput.validate_prefix/validate_workload` independently refuse intersections. A changed projection cannot convert a same-token/different-image root into a valid hit: `image_keys/image_ranges` discriminate it, and the authority falls back to a legitimate earlier pair/miss.

No alpha.2 request transmits a desired KV frontier. With current whole-image-safe publication, a genuine compatible pair cannot become an intersecting hit merely because Harness changes history. Upstream overlap support is therefore **not an established missing reachable requirement**. Supporting it would entail numerical/state alignment work, not simply relaxing a guard. No such work is justified.

## 4. Changed canonical prompts, eviction and sources

Harness alpha.2 `packages/llm/llm-deepseek/src/images.ts:prepareImages` first projects logged offloads to deterministic text, then reads every remaining attachment through the official store. `adapter.ts:request` serializes that **current** projection; no provider KV handle, cache invalidation or resume command is sent. Official offload/compaction implementations own durable selection/replacement, not the provider.

Locally `PairedCheckpointAuthority.acquire` looks up current IDs through N−2 with image key ranges, leases the selected root, validates the complete target/rings and restores independent mutable handles. Invalid/missing paired payloads are invalidated through the same authority and an earlier real pair or miss is selected. A target-only hint is never a hit. Independent Messages accepts actual C=0 or a genuinely restored whole-image-safe C>0 and charges all uncovered occurrences fresh. It never discards a healthy selected pair to force C=0. `acquire_retained`'s exact Chat lease failure policy is not imposed on Harness Session restoration.

The changed-projection evidence executes real Recipe encoding and cache selection for changed bytes, reorder, movement, shortened history, assistant rewrite and unchanged control. Native evidence separately establishes reconstruction and paired settlement. Alpha.2 E2E request 16 handles official offload at **C=0**; request 17 runs the native compaction summary; request 18 reconstructs the compacted projection at **C=0**; request 19 restores **C=2368** and encodes new A. Rc.2 integrated request `06:8` restores **C=3394** before surviving H/I plus newly acquired A, establishing the mixed historical suffix lifecycle separately.

These are canonical input recomputations, **not tool execution replay**. A later `read_image` is a new Harness effect with a new exact ID. Reattached/reacquired bytes undergo ordinary new-input identity checks; same bytes do not confer old-occurrence position or KV ownership. Alpha.2 actually reacquired A; arbitrary human reattachment UI paths are not separately qualified, but require no new provider operation.

### Real residual availability boundary, not hidden parity

`production_mtp.py:_schedule_waiting` installs a pre-restore admission callback whenever total planned patches exceed **36,864**. That callback requires **C ≥ required_image_frontier**, complete exact historical coverage and supported pair layout. Therefore a valid larger projected history with some covered and some uncovered **historical** images can reject even when uncovered work by itself would fit the fresh budget. A full miss above the fresh budget also rejects. Removing the old paired-byte ceilings did **not** remove this rule.

Concrete exposure: offload/compaction or eviction changes the prefix of a larger retained image history; not all surviving historical occurrences remain covered. This is proven unsupported source behavior, not an observed failure in the accepted alpha.2 workload. The supported reconstruction envelope is aggregate patches within 36,864 (and its independent body/source/context constraints). Current source does not promise recovery for arbitrary default official-service budgets. Runtime resource rejection does not automatically cause official offload.

No new evidence warrants reopening the closed resource campaign. If that larger workload is independently requested, the minimum first step is a **single model-free real-Recipe projection with actual earlier pair/miss and exact patch accounting**, identifying which current guard refuses. That would determine whether the issue is overly conservative mixed-history admission or genuine fresh-work excess. Only the former could motivate a narrowly reviewed admission change plus affected numerical/resource evidence; automatic fallback, new cache ownership or a chunked-Vision redesign is not recommended here.

## 5. Scheduler, preemption, Target/DSpark and output lifecycle

DeepInfer `csrc/engine/scheduler.hpp` allocates finite block **and state** capacity, clones/pins forked state, and adjusts prefill chunk endpoints to avoid splitting image units (`_adjust_chunk_size`, lines 217–260). `fork_seq` (1059 onward) limits reuse to `min(parentC,N−1)`. `_preempt` (766 onward) either finishes preempted work or calls `Sequence::reset_for_recompute`, frees state/blocks and requeues it. Recompute is configurable, unavailable to the completion-only engine without a prefill channel, and disabled for structured-output state. `sequence.hpp` explicitly resets rolling cache/inflight/MTP draft information; `process_outputs` discards stale preempted in-flight results. This is **conditional engine-local resource recovery**, not universal resumability, session persistence or exactly-once external effects.

Local ordinary serving serializes native execution (`max_num_seqs=1`), so copying multi-request GPU preemption is not necessary to implement a client request pattern. Complete immutable pairs bind all 40 target layers and three committed DSpark rings, execution identity, canonical IDs and covered images at one C. Speculative draft/proposal/prediction and request RNG state are not reusable checkpoints. Existing N−2 capture → N−1 append → P5 handoff and the sole Scheduler BatchGenerator remain the execution topology; recurrent ring trimming to mimic upstream N−1 lookup would be unsafe and unnecessary.

`ProductionScheduler._retire` settles/quiesces before publishing and retires the executable owner; mutation/settlement/ownership failures burn state and fail closed. Queued cancellation releases sources without native work. Active cancellation is shielded across worker mutation and settles or burns before another request. No SSE receipt is a canonical-token acknowledgement. The alpha.2 cancellation request settles C=4135, but the next request correctly selects compatible **C=3944**, not a root containing unseen output. Unseen suffixes do not enter Harness history or authorize tool effects.

The native route relies on `RecipeSemanticGuard` / Messages semantic session and accumulator, not DeepInfer token output as a second protocol converter. `production_mtp.py:step` withholds a `tool_use` suffix until same-worker canonical settlement, and errors/cancellation cannot fabricate successful `message_stop`. Existing alpha.2 evidence joins exact complete native/wire events for 25 normal responses, plus an explicitly incomplete cancellation prefix. Tool IDs/results remain Recipe/Harness authority.

**Consequence:** serial scheduling, different prefix capture points and fail-closed active failure recovery are justified MLX/paired-state differences. Harness resume is new projection/execution, not a requirement to resurrect an interrupted native request. No upstream reset routine can safely be transplanted as an HTTP retry or tool-effect recovery mechanism. Arbitrary cancellation during effectful tool delivery remains unverified, not a new proven defect.

## 6. Files, expiry and restart recovery

Alpha.2 `adapter.ts` / `request-files.ts:RequestFiles` already owns bounded stale-ID recovery: classify missing/expired/invalid file errors, invalidate named mappings (or affected candidates), retry at most once, and re-resolve current attachment versions. Upload failure can select request-wide bounded inline fallback. `images.ts` checks represented raw/base64 budgets and emits `IMAGE_OFFLOAD_REQUIRED` **before HTTP**; the official offload plugin handles that code, not arbitrary Runtime 400/503 errors.

Local `image_files.py:ImageFiles.snapshot` returns `file not found or expired: <id>` / `file_not_found` before inference; `resolve_messages` snapshots supported user/nested tool-result sources before Recipe conversion. This matches the stale-ID classifier. `tests/test_image_files.py:test_stale_scope_expiry_delete_before_execution` covers pre-native rejection. Current master supports paginated listing needed by official quota reclamation, unlike older Production. Files byte lifetime and executable paired lifetime are deliberately independent.

After Runtime restart, provider IDs and KV can both be absent. Harness may refresh from its own attachment bytes; the next complete independent Messages request can reconstruct within the usual envelope. Source establishes these seams, **not** a new real-model restart/expiry E2E claim. The smallest evidence to resolve that unverified composition would be an isolated model-free official `RequestFiles`/adapter exchange against process-local Files: invalidate a cached ID, observe one reupload/retry and unchanged exact-ID Messages body, with execution stubbed. No implementation recommendation follows from its not having been run here.

The provider cannot recover deleted client attachment bytes, and upstream DeepInfer's conditional omission of cached image binaries is not a durable image reacquisition service. No independent runtime image-history manager, durable Files store, Session synchronizer or second KV authority is justified.

## 7. Other relevant differences and deliberate exclusions

- DeepInfer `worker/base.py:profile_num_available_blocks` profiles Torch/non-Torch memory, reserves state/copy buffers and sizes a device KV pool. Scheduler block/state admission and chunked Vision bound different allocations from MLX's sequential CPU preparation, transient image embeddings, paired clones and allocator. This audit finds no fresh defect requiring that CUDA/NPU pool design. Existing fresh-patch/body/Files bounds remain availability limits, not physical-headroom guarantees; the soft-cap campaign stays closed.
- Broad numerical equality is **not established**. The reconstruction reports retain significant MTP-versus-Ordinary/state observations and partition-dependent floating differences; C2 remains PARTIAL. Native lifecycle/frontier/identity correctness and successful bounded application operation do not prove universal logits or token equivalence. DeepInfer supplies no evidence that relaxing these boundaries is safe. No regression or concrete alpha.2 failure here warrants a numerical campaign. For a future concrete discrepancy, preserve the exact current prompt, bytes, selected paired state and schedule, then compare the affected boundary—not a new blanket full-model acceptance.
- Session forks/restores, Skills, plugin inventories, Goal and tool registry updates are primarily Harness history projection plus Recipe encoding, not separate inference features. Alpha.2 E2E already exercises representative changed projections, including all-deferred and restored Harness Session. No new Messages converter or Session owner is needed.
- `tool_removal` is deferred for absent authoritative Recipe removal encoding and remains explicitly rejected. It is not reopened via DeepInfer. Session-log ingestion remains disabled; no false acknowledgement or duplicate Session storage is proposed.
- Structured output, distributed deployment, backend kernels/graphs, unrestricted batch serving, native KV persistence, Windows qualification and same-process model reload/reclamation have no newly established dependency for the supported route. They are not follow-up tasks.
