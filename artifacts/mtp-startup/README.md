# Fresh MTP startup evidence

See `docs/mtp-startup-investigation.md` for causal interpretation and commands.
Base is `12182b3`; R1 identity and fixtures were not edited.

- `r1-mtp-final.json`, `r1-off-after.json` and top-level gate receipts/logs:
  full independently admitted R1 lanes, PASS / CONFORMANT, 24 gates each.
  The final MTP receipt's candidate source hashes match all three changed runtime
  files. OFF execution is unchanged; its run precedes the MTP-only defensive
  mismatch/finalizer cleanup refinement.
- `summary.json`: regenerated by `tools.summarize_mtp_startup`; compares final
  uninstrumented metrics against the existing `mtp-verification/r1-mtp-gates`
  baseline and checks direct-control token, target/ring digest and frontier
  equivalence. Tool-call UUIDs are explicitly excluded from response comparison.
- `controls-production.json`: two passes over 64/128/256/292/512/1024 real prompt
  positions, alternating late wiring, joint evaluation, production early lease.
  Includes the ordinary native constructor's second limit call. Eight generated
  token IDs and settled state digests are retained for every case.
- `controls.json`: earlier causal control suppressing only the nested native
  limit call. Not the production implementation. Its successful-path results
  agree with the production-lease control.
- `phases-detail.json.gz` / `fixture-detail.json`: old-path coarse native call
  attribution, including the ~1.3 s late `set_wired_limit`.
- `phases-joint-split.json.gz` / `fixture-joint-split.json`: old-path serialized
  hidden/target-cache evaluation before DSpark projection, disproving seconds of
  DSpark model compute and testing joint evaluation.
- `phases-after.json.gz` / `fixture-after.json`: final runtime split-context trace,
  including memory metadata and both limit acquisitions.
- `phases-first-proposal.json.gz` / `fixture-first-proposal.json`: bounded first
  `next_token` trace through actual native activation and proposal computation.
- `mlx-source-evidence.json`: read-only upstream MLX 0.32.2 source identification
  and hashes; no native rebuild, patch or residency-set tuning.
- `resources-tests.log`: 7 resource lifetime/failure/transfer tests.

Phase timestamps are nested host wall times, not additive GPU durations. Cold
load/first-use is retained but excluded from warm performance comparisons. Only
uninstrumented R1 metrics and direct controls support the speedup claim.

Excluded early-wiring observer attempts are retained as FAIL receipts/logs:
one used the wrong import for `mlx_lm.generate`, another launched during source
identity drift and correctly failed closed. Other initial CLI/shutdown/digest
harness mistakes are disclosed in the report. No excluded run is performance or
qualification evidence.

Model operands, generated OFF source extraction, persisted KV tensors and build
products are intentionally not committed. The unchanged R1 command regenerates
them; source delivery and numerical authority remain in their existing owners.
